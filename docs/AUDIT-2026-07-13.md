## Scopo del software (verificato sul codice)

StreamFlow è un client desktop Electron per streaming audio live verso server Icecast/Shoutcast e AzuraCast (DJ Mode / harbor Liquidsoap). Cattura l'audio da un dispositivo Windows (DirectShow), lo encoda in MP3 con FFmpeg e lo trasmette via HTTP PUT. Funzionalità: VU meter, timer di sessione, invio metadata "Now Playing" (updinfo via raw socket BUTT-compatibile), wizard di auto-configurazione AzuraCast, profili server, log eventi a video, controllo volume input, auto-reconnect con backoff (da v0.5.7).

Architettura a 3 processi: **Main** (lifecycle, FFmpeg, socket metadata, API AzuraCast) ↔ **Preload** (contextBridge) ↔ **Renderer** (React 19 + Zustand + Tailwind).

## ⏳ Aperto / da verificare

### Rischio accettato — S2: credenziali nella command line di FFmpeg

L'header `Authorization: Basic <base64(user:password)>` è passato come argomento di riga di comando a FFmpeg: qualunque processo/utente locale lo legge da Task Manager / `wmic process get commandline`, e Base64 si decodifica banalmente. È un **limite strutturale di FFmpeg CLI** (non legge headers da stdin/env), comune a tutti i client di questo tipo. Mitigazioni applicate in v0.5.8: `windowsHide: true` su tutti gli spawn, gli `args` non vengono mai loggati, commento di documentazione nel codice ([ffmpeg-manager.ts](../src/main/streaming/ffmpeg-manager.ts), sezione spawn). Anche l'URL `http://` espone la password in transito sulla rete: Icecast source su TLS spesso non è disponibile — rischio da tenere presente lato server.

**Eliminabile solo** cambiando strategia di encoding/trasporto (es. libreria di streaming in-process invece di FFmpeg CLI) — fuori scope attuale.

### Test live pendenti (fix implementati ma non verificati con server reale)

1. **Auto-reconnect (v0.5.7):** avviare stream su Runtime Radio, staccare rete o riavviare Liquidsoap → verificare countdown ambra nell'header ("Riconnessione tra Xs (tentativo N/5)"), ripresa dello stream, azzeramento del contatore dopo la ripresa, annullamento premendo ON AIR durante l'attesa.
2. **VU stereo reale (v0.5.8):** con device stereo i meter L/R devono differire; con mic mono devono essere identici (duplicazione volontaria). Minimizzando la finestra il mic deve essere rilasciato (indicatore privacy OS spento) e riattivarsi al ripristino.
3. **Regression pass:** stop senza toast d'errore, volume 0% = mute reale, wizard AzuraCast con URL `http://` (redirect), metadata con caratteri speciali nel titolo.
