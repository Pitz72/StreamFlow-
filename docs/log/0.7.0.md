# v0.7.0 — Runtime Radio Edition: preset interno + tendina DJ + password cifrata

## Cambio di direzione (dichiarato dall'utente 2026-07-24)

StreamFlow non è più un client generico da generalizzare verso Icecast/Shoutcast: diventa il **software ufficiale interno di Runtime Radio**. La configurazione esatta validata in diretta reale (v0.6.0, live di ~2h30 senza errori) è preimpostata nel codice; l'utente inesperto sceglie solo il proprio **nome utente** dalla tendina e digita la **password**. Fine.

Questo ribalta la priorità "generalizzazione multi-sistema" della roadmap del 13 luglio: quella strada è archiviata (recuperabile in futuro, il core HTTP PUT resta generico).

## Cosa è stato fatto

### 1. Preset di stazione (`src/renderer/config/stationPreset.ts`)
Valori fissi, ricavati dalla configurazione realmente usata nella live di validazione (recuperata dal localStorage dell'app installata):

| Parametro | Valore |
|---|---|
| Host | `player.runtimeradio.com` |
| Porta (harbor Liquidsoap) | `8005` |
| Mount | `/` |
| Bitrate | `192 kbps` MP3 |

L'elenco DJ è un array `djs: { username, displayName }[]` nello stesso file — oggi contiene solo Simone. **Per aggiungere un DJ: aggiungere una riga e rilasciare una build.** La tendina ha anche "Altro utente…" (inserimento manuale) per i casi non in elenco.

### 2. Store semplificato (`useStore.ts`)
- `streamConfig` inizializzato dal preset; il `merge` custom di zustand/persist **riforza sempre** host/porta/mount/bitrate dal preset — una config vecchia (pre-0.7.0) nel localStorage non può sopravvivere alla migrazione. Conservati: `icecastUser`, `inputGain`, device selezionato, artista Now Playing.
- Rimossi: profili server (`profiles`, save/load/delete) e contesto AzuraCast (`azuraCastUrl`/`apiKey`/`stationId`) — non usati da nessuno dopo la rimozione del wizard.
- Nuovo flag persistito `rememberPassword` (default `true`).

### 3. Password cifrata (safeStorage)
- Nuovo modulo main `src/main/credentials.ts`: `savePassword`/`loadPassword`/`deletePassword` su `userData/dj-credentials.json` (mappa username → ciphertext base64 di `safeStorage.encryptString`, cioè DPAPI su Windows: decifrabile solo dall'account utente del PC).
- IPC `dj-password-save/load/delete` + preload `saveDjPassword`/`loadDjPassword`/`deleteDjPassword`.
- Flusso: la password viene salvata **solo al primo status `connected`** (mai una password sbagliata); precompilata al mount dell'app e al cambio utente nella tendina; cancellata deselezionando "Ricorda".
- Nota: il timeout di cortesia di 5s in `ffmpeg-manager` (connessione assunta se il server è silenzioso) può in teoria salvare una password non verificata — caso remoto (auth sbagliata produce errore prima), accettato.

### 4. Pannello Configurazione ridotto
Banner "Runtime Radio — client interno" → tendina Nome utente → Password + checkbox Ricorda → Audio Input Device → riepilogo connessione **in sola lettura** (diagnostica). Eliminati: wizard AzuraCast, profili, campi host/porta/mount/utente/bitrate editabili.

### 5. Rimozioni
- `src/renderer/components/AzuraCastWizard.tsx` — eliminato.
- `src/main/azuracast/azuracast-api.ts` + handler IPC `azuracast-*` + tipi in `env.d.ts` — eliminati. Se un domani si vorrà sincronizzare l'elenco DJ via API AzuraCast, il modulo si recupera dalla history git (`git show 2124a8f:src/main/azuracast/azuracast-api.ts`).
