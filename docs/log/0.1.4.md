# Runtime StreamFlow v0.1.4 Log

## Data: 2026-03-05
## Versione: 0.1.4 (Grave Fix: Electron Lifecycle & Process Cleanup)

### Stato: IMPLEMENTED
Risolto il problema dei processi FFmpeg orfani alla chiusura dell'applicazione e implementata la corretta gestione del ciclo di vita Electron.

### 🟠 Fix Grave: Nessun Lifecycle Event Electron

#### Diagnosi
Il file `main.ts` mancava di due handler fondamentali per il ciclo di vita Electron:
1. **`window-all-closed`**: Su Windows/Linux, chiudere la finestra non terminava il processo dell'app. L'icona spariva ma il processo restava attivo nel Task Manager.
2. **`before-quit`**: Nessuna logica di cleanup veniva eseguita prima della chiusura. Se l'utente chiudeva l'app durante lo streaming, il processo `ffmpeg.exe` restava orfano in background, bloccando il dispositivo audio.

#### Effetti del bug
- **Processi zombie**: Dopo chiusura dell'app durante streaming, `ffmpeg.exe` restava attivo in background indefinitamente.
- **Dispositivo audio bloccato**: L'utente non poteva usare il microfono in altre applicazioni finché non terminava ffmpeg manualmente (`taskkill`).
- **Processo Electron orfano**: Su Windows, il processo `streamflow.exe` restava nel Task Manager dopo aver chiuso la finestra.

#### Soluzione Applicata

**1. Funzione di cleanup esportata (`src/main/ipcp.ts`)**

Aggiunta una nuova funzione `cleanupIpc` che ferma lo StreamManager in modo sicuro:

```typescript
export const cleanupIpc = () => {
    if (streamManager) {
        streamManager.stop();   // Chiama taskkill su Windows per terminare l'albero FFmpeg
        streamManager = null;   // Libera il riferimento
    }
};
```

**2. Lifecycle events in `src/main/main.ts`**

Aggiunti due handler al ciclo di vita dell'app:

```typescript
// Termina l'app quando tutte le finestre vengono chiuse (Windows/Linux)
app.on('window-all-closed', () => {
    if (process.platform !== 'darwin') {
        app.quit();
    }
});

// Cleanup FFmpeg PRIMA della chiusura
app.on('before-quit', () => {
    cleanupIpc();
});
```

**Flusso di chiusura risultante**:
```
Utente chiude finestra
    → window-all-closed: app.quit() (su Windows/Linux)
        → before-quit: cleanupIpc()
            → streamManager.stop()
                → taskkill /pid <ffmpeg_pid> /f /t
                    → ffmpeg.exe terminato, dispositivo audio rilasciato
```

**Nota macOS**: Su macOS (`darwin`), `window-all-closed` non chiama `app.quit()`, rispettando il comportamento standard macOS dove le app restano attive anche senza finestre aperte.

### Note Tecniche
- `before-quit` viene emesso prima di `will-quit`, garantendo che il cleanup avvenga il prima possibile nel ciclo di chiusura.
- La funzione `stop()` dello StreamManager utilizza `taskkill /pid <pid> /f /t` su Windows, che forza la terminazione dell'intero albero dei processi associati a FFmpeg.
- Se l'app viene terminata forzatamente (es. `taskkill /f` da Task Manager), il `before-quit` event non viene emesso. In quel caso estremo, FFmpeg potrebbe comunque restare orfano.
