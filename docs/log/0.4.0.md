## Feature: Now Playing / Metadata

### Architettura

**Protocollo:** Icecast `updinfo` — standard HTTP GET universale compatibile con tutti i server Icecast-based:
```
GET /admin/metadata?mount=/live&mode=updinfo&song=Artist+-+Title
Authorization: Basic base64(user:password)
```

**Flusso dati:**
```
Renderer (NowPlayingPanel)
    → IPC 'update-metadata' { artist, title }
    → MetadataManager.send()
    → HTTP GET → Icecast/AzuraCast server
```

### Nuovi file

**`src/main/streaming/metadata-manager.ts`**
Classe `MetadataManager` con:
- `setConfig(config)` — memorizza le credenziali di connessione al momento dello start-stream
- `clearConfig()` — chiamato allo stop-stream
- `send(artist, title)` — HTTP GET al server con timeout 5s, usa `http` nativo Node.js

**`src/renderer/components/NowPlayingPanel.tsx`**
Componente UI con:
- Campo **Show Name** — identità della trasmissione, persistita in localStorage
- Campi **Artist** + **Title** — now playing corrente, artist persistito, title session-only
- Pulsante **Invia** — attivo solo durante streaming, con feedback visivo (✓ / ✗)
- Auto-submit su tasto Invio nei campi Artist/Title
- Hint quando offline: "I metadati verranno inviati automaticamente all'avvio dello stream"

### Auto-send all'avvio stream

In `App.tsx`, quando `onStreamStatus` riceve `'connected'`, i metadati correnti vengono inviati automaticamente se almeno uno dei campi è valorizzato. Usa `artist || showName` come fallback per garantire sempre un contenuto utile.

### Modifiche a file esistenti

- `src/main/ipcp.ts`: handler `update-metadata` + salvataggio config in MetadataManager a ogni `start-stream`
- `src/preload/index.ts`: esposto `updateMetadata(meta)` via contextBridge
- `src/renderer/env.d.ts`: aggiunto tipo `updateMetadata` in `ElectronAPI`
- `src/renderer/store/useStore.ts`: aggiunto `StreamMetadata` interface + stato `streamMetadata` + `setStreamMetadata` + partialize (showName + artist persistiti, title no)
- `src/renderer/App.tsx`: import NowPlayingPanel, destructuring `streamMetadata`, auto-send su connected

## Feature: AzuraCast Auto-Config

### Architettura

**`src/main/azuracast/azuracast-api.ts`**
Modulo con due funzioni esportate:
- `fetchStations(baseUrl, apiKey)` → `GET /api/stations` → lista stazioni
- `fetchStationDetail(baseUrl, apiKey, stationId)` → `GET /api/station/{id}` + `GET /api/station/{id}/streamers` → host/port/mount + lista DJ

Usa `http`/`https` nativi Node.js con supporto HTTPS automatico. Timeout 8s. Derivo host/port/mount dalla `listen_url` della stazione.

**`src/renderer/components/AzuraCastWizard.tsx`**
Wizard a step con stato locale (nessuna modifica allo store Zustand):
1. **Idle**: pulsante "Configura da AzuraCast" + icona ⓘ
2. **Step 1**: inserimento URL + API Key → "Carica stazioni"
3. **Step 2**: dropdown stazioni → "Carica DJ / Streamer"
4. **Step 3**: mostra host:port/mount + dropdown streamer → "Applica configurazione"

Il pulsante ⓘ mostra istruzioni inline su come ottenere URL e API Key da AzuraCast (Profilo → API Keys). La password non viene mai caricata dall'API — rimane campo manuale.

**Applicazione**: il pulsante "Applica" chiama `setStreamConfig({ host, port, mount, icecastUser })` — sovrascrive solo i campi rilevanti, lascia bitrate e password invariati.

### Modifiche a file esistenti

- `src/main/ipcp.ts`: handler `azuracast-fetch-stations` e `azuracast-fetch-station-detail`
- `src/preload/index.ts`: esposti `azuraCastFetchStations` e `azuraCastFetchStationDetail`
- `src/renderer/env.d.ts`: aggiunte interfacce `AzStation`, `AzStreamer`, `AzStationDetail` e metodi in `ElectronAPI`
- `src/renderer/components/SettingsPanel.tsx`: import e rendering `AzuraCastWizard` in cima al pannello (con `relative` sul container per il posizionamento tooltip)

## Note architetturali

- **Universalità**: Now Playing via updinfo funziona su tutti i server Icecast-based, non solo AzuraCast. Chi usa Shoutcast o CentovaCast beneficia della feature senza configurazione aggiuntiva.
- **Sicurezza**: l'API Key AzuraCast non è persistita (solo in stato locale del componente wizard, non nel Zustand store). La password DJ rimane sempre manuale.
- **Separazione**: MetadataManager vive nel main process e non dipende dallo store Zustand — riceve la config solo tramite IPC, evitando accoppiamento tra renderer state e main process.
