# Runtime StreamFlow v0.0.7 Log

## Data: 07/02/2026
## Versione: 0.0.7 (Patch: HTTP Protocol Switch)

### Stato: IMPLEMENTED
Cambiato radicalmente il metodo di streaming per emulare il comportamento client di BUTT (Broadcast using this tool), necessario per supportare le configurazioni DJ di AzuraCast.

### Modifiche Core (Backend - ffmpeg-manager.ts)

1.  **Protocol Switch**:
    - Abbandonato il protocollo `icecast://` che falliva con mount point di root (`/`).
    - Adottato il protocollo `http://` con metodo `PUT`.
    - Questo permette di inviare lo stream direttamente alla root del server, comportamento standard per i mount point DJ.

2.  **Argomenti FFmpeg**:
    - Aggiunto `-method PUT`: Specifica che stiamo inviando dati al server.
    - Aggiunto `-content_type audio/mpeg`: Header HTTP necessario per dire al server che stiamo inviando MP3.
    - URL Target: `http://user:password@host:port/mount` (o `/` se mount non specificato).

3.  **Compatibilità**:
    - Questa configurazione è specifica per emulare client come BUTT che supportano nativamente questo tipo di connessione "raw" HTTP.
    - Mantiene la compatibilità con la pulizia dei nomi device Windows introdotta nella v0.0.4.

### Test Consigliati
1.  Configurare Host/Port del server AzuraCast.
2.  Impostare "Icecast User" (es. nome DJ).
3.  Impostare Mount Point a `/` (o lasciarlo vuoto se gestito così).
4.  Avviare lo streaming.
5.  Verificare che il server riceva lo stream (HTTP 200 OK).

Patch critica per l'utilizzo con account DJ AzuraCast.
