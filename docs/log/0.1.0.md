# Runtime StreamFlow v0.1.0 Log

## Data: 2026-02-08
## Versione: 0.1.0 (Critical Protocol Fix: Headers & Expect: 100-continue)

### Stato: IMPLEMENTED
Risolto bug critico che causava la disconnessione immediata ("Connection Reset by Peer", Exit Code -10054) con server AzuraCast/Icecast moderni.

### Modifiche Core (Backend - ffmpeg-manager.ts)

1.  **Rimozione Header "Expect: 100-continue"**:
    - *Diagnosi*: FFmpeg invia di default l'header `Expect: 100-continue` nelle richieste HTTP PUT. Molti server proxy o configurazioni Icecast recenti non gestiscono questo handshake e resettano la connessione.
    - *Soluzione*: Forzata la rimozione dell'header tramite flag `-headers "Expect:"`.

2.  **Impostazione User-Agent**:
    - *Modifica*: Impostato `User-Agent: FMLE/3.0` (Flash Media Live Encoder).
    - *Motivo*: Aumenta la compatibilità emulando un encoder standard industriale, riducendo il rischio di blocchi lato server.

3.  **Configurazione FFmpeg Finale**:
    ```bash
    -content_type audio/mpeg
    -method PUT
    -chunked_post 0
    -headers "User-Agent: FMLE/3.0\r\nExpect:\r\nIce-Public: 1\r\n"
    ```
