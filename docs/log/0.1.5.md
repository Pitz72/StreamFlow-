## Versione: 0.1.5 (Grave Fix: Type Safety per IPC Bridge)

### Stato: IMPLEMENTED
Eliminate tutte le soppressioni di tipo (`@ts-ignore`) dalle chiamate IPC verso Electron, sostituendole con type declarations formali.

### 🟠 Fix Grave: Nessun Type Definition per `window.electronAPI`

#### Diagnosi
Il componente `App.tsx` conteneva **5 direttive `@ts-ignore`** per sopprimere gli errori TypeScript relativi a `window.electronAPI`, un oggetto iniettato dal preload bridge tramite `contextBridge.exposeInMainWorld()`.

Senza type declarations:
- Zero autocompletamento per le API IPC nel renderer.
- Nessun controllo sui parametri passati a `startStream()` — è possibile passare un oggetto malformato senza errori.
- Se un metodo viene rinominato nel preload (es. `stopStream` → `disconnect`), il compilatore non segnala l'errore — il bug si manifesta solo a runtime.

#### Soluzione Applicata

**1. Nuovo file `src/renderer/env.d.ts`**

Creato un file di dichiarazioni TypeScript che estende l'interfaccia globale `Window`:

```typescript
interface ElectronAPI {
    startStream: (config: {
        inputDeviceName: string;
        host: string;
        port: string;
        password: string;
        mount: string;
        icecastUser?: string;
    }) => Promise<void>;
    stopStream: () => Promise<void>;
    onStreamStatus: (
        callback: (status: 'disconnected' | 'connecting' | 'connected' | 'error', message?: string) => void
    ) => () => void;
}

interface Window {
    electronAPI: ElectronAPI;
}
```

Punti chiave:
- La config di `startStream` è tipizzata con gli stessi campi di `StreamConfig` del backend.
- `onStreamStatus` dichiara il return type come `() => void` (la funzione di cleanup introdotta in v0.1.3).
- Il parametro `status` è tipizzato come union literal `'disconnected' | 'connecting' | 'connected' | 'error'`, garantendo coerenza con lo store Zustand.

**2. Rimozione `@ts-ignore` da `App.tsx`**

Rimosse tutte e 5 le direttive `@ts-ignore`:
- Riga 20 → `if (window.electronAPI && ...)` — ora riconosciuto dal tipo `Window`.
- Riga 22 → `window.electronAPI.onStreamStatus(...)` — ora type-safe.
- Riga 41 → `if (window.electronAPI)` — ora riconosciuto.
- Riga 54 → `window.electronAPI.startStream(...)` — ora validato dal compilatore.
- Riga 57 → `window.electronAPI.stopStream()` — ora validato.

### Benefici
- **Compilatore come guardiano**: Qualsiasi modifica al preload (aggiunta/rimozione metodi) viene segnalata immediatamente nel renderer.
- **Autocompletamento IDE**: Lo sviluppatore può navigare i metodi disponibili con Ctrl+Space.
- **Documentazione inline**: L'interfaccia `ElectronAPI` funge da contratto formale tra Main e Renderer.

### Note Tecniche
- Il file `env.d.ts` viene automaticamente incluso da `tsconfig.app.json` tramite `"include": ["src/renderer"]`.
- Non è necessario importarlo esplicitamente — TypeScript lo riconosce come file di dichiarazione ambientale.
- Il pattern `interface Window { ... }` è la modalità standard per estendere tipi globali in TypeScript senza modificare `lib.dom.d.ts`.
