# Runtime StreamFlow v0.0.4 Log

## Data: 2026-02-07
## Versione: 0.0.4 (Patch: Advanced Device Logic)

### Stato: IMPLEMENTED
Risolti problemi critici di compatibilità con i dispositivi audio su Windows e con credenziali Icecast complesse.

### Modifiche Core (Backend)

1.  **Audio Device Name Cleaning**:
    - *Problema*: Su Windows, i dispositivi audio possono avere prefissi come "Communications - " o "Default - " e suffissi ID hardware come "(19f7:0037)" che FFmpeg non riconosce nel filtro `dshow`.
    - *Soluzione*: Implementata una logica di pulizia regex in `ffmpeg-manager.ts` prima dello spawn del processo.
    - *Logica*:
      ```typescript
      const cleanDevice = inputDeviceName
          .replace(/^(Communications|Default) - /, '')
          .replace(/\s\([0-9a-fA-F]{4}:[0-9a-fA-F]{4}\)$/, '');
      ```
    - *Esempio*: "Default - Microfono (Realtek Audio) (045e:070f)" -> "Microfono (Realtek Audio)".

2.  **Safe Icecast URL Construction**:
    - *Problema*: Password o username contenenti caratteri speciali (es. `@`, `/`, `:`) rompevano la stringa di connessione URL-like passata a FFmpeg.
    - *Soluzione*: Applicato `encodeURIComponent` a user e password.
    - *Formato*: `icecast://safeUser:safePass@host:port/mount`

3.  **Debug Logging**:
    - Aggiunti log dettagliati nel backend per verificare:
      - Nome dispositivo originale (dal frontend).
      - Nome dispositivo pulito (passato a FFmpeg).
      - Target URL (con credenziali mascherate).
