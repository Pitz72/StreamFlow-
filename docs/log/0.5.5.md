# v0.5.5 — Fix visibilità StreamLog

## Problema

In v0.5.3 era stato introdotto il componente `StreamLog` (barra log a piè di pagina, espandibile). All'utente non risultava visibile.

## Diagnosi

1. **Barra troppo poco contrastata all'avvio.** Sfondo `bg-stone-900/90` (con alpha) su parent `bg-stone-950`, padding ridotto (`py-1.5`), bordo sottile (`border-t border-stone-800`) e contenuto vuoto (`"nessun evento"`). Risultato: ~24px alti di stripe quasi indistinguibile dal background. Facile non riconoscerla come elemento UI.
2. **Nessun evento di sistema iniziale.** Il `LOG_EVENT` veniva emesso solo quando partiva uno stream o un invio metadata. Su app appena avviata la barra restava vuota.
3. **Mancava `shrink-0` esplicito** sul wrapper: in alcuni stati di rendering del flex column la barra avrebbe potuto venire compressa a 0 se main richiedeva più spazio.

## Fix

### `src/renderer/components/StreamLog.tsx`
- Wrapper: `shrink-0 bg-stone-900 border-t-2 border-stone-700 relative z-10` (era `bg-stone-900/90 border-t border-stone-800 backdrop-blur-sm`).
- Padding bar collassata: `py-2` (era `py-1.5`).

### `src/main/ipcp.ts`
- Aggiunto evento iniziale `LOG_EVENT` su `webContents.once('did-finish-load')`: emette `system / info / "StreamFlow pronto — in attesa di eventi."` così la barra ha sempre un evento visibile dal primo frame.

### Versione
- `package.json`: 0.5.4 → 0.5.5
- Header UI: v0.5.4 → v0.5.5
