# Runtime StreamFlow v0.2.3-rc Log

## Data: 2026-03-05
## Versione: 0.2.3-rc (Fix VuMeter e FFmpeg Error Visibility)

### Stato: IMPLEMENTED
Risolti due bug collegati emersi nell'RC precedente:
1. `OverconstrainedError` all'interno del VuMeter visuale, dovuto al passaggio di stringhe di device nativi Windows (DSHOW) nelle API W3C standard di Chromium che supportano unicamente ID hash interni (`default`, `8bd42...`).
2. Errori silenziosi di avvio di FFmpeg, tradotti nell'inintelligibile Exit Code `4294957242`.

### 🔴 Fixes Applicati

#### 1. VuMeter Device Mapper (`useAudioVisualizer.ts`)
Interrogare il device corretto per l'analisi FFT di Chromium richiedeva l'hash ID di Google Chrome, ma l'interfaccia ormai forniva la stringa DSHOW (ex: `"Microfono (Realtek)"`). Ho introdotto una fase intermedia di translation:
- Il React Hook ora recupera temporaneamente i permessi microfonici (`getUserMedia({ audio: true })`) per poter leggere liberamente le label in chiaro da `navigator.mediaDevices.enumerateDevices()`.
- Un algoritmo di fuzzy matching cerca il device Chrome la cui stringa "Label" contiene (o viceversa) l'identificativo esatto fornito da FFmpeg DShow.
- Viene riemesso il feed audio fornendo a Chromium il suo DeviceHash nativo `{ exact: deviceId }` calcolato automaticamente. L'Error *Overconstrained* è estinto.

#### 2. Stderr IPC Bubbling (`ffmpeg-manager.ts`)
Con gli installer di produzione `.exe`, Console.log eseguiti da NodeJS non sono visibili nei DevTools del frontend (gestiti diversamente in Main Process mode). FFmpeg probabilmente incontra un blocco di porta, una password Icecast errata, o una violation Sharing del device da parte di altre applicazioni.
- Implementato l'accumulatore log in pipe che spia a run-time i dati `stderr` di FFmpeg e bufferizza le ultime stringhe.
- In caso l'app si chiuda in `error` ritornando uno stato anomalo (`code !== 0`), lo `stderr` grezzo generato dalla command-line al backend emerge tramite un bubble IPC. Sarà ora l'interfaccia UI in rosso, al posto dell'inutile "Exited with code xxx", a comunicare esplicitamente "FFmpeg Crash: [testo reale del fallimento come *401 Unauthorized*, *Invalid Argument* ecc.]" .
