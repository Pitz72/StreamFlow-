# Runtime StreamFlow v0.0.5 Log

## Data: 2026-02-07
## Versione: 0.0.5 (Patch: State Persistence Refactor)

### Stato: IMPLEMENTED
Ottimizzata la gestione della persistenza dello stato globale per prevenire incoerenze al riavvio dell'applicazione.

### Modifiche Core (Frontend Store)

1.  **Global State Refactoring**:
    - Spostati `isStreaming` e `streamStatus` da stato locale (`App.tsx`) a stato globale (`useStore.ts`).
    - Questo centralizza la logica di stato e facilita l'accesso da altri componenti.

2.  **State Persistence Exclusions**:
    - *Problema*: `persist` salvava l'intero stato, incluso `isStreaming`. Se l'app veniva chiusa mentre era "ON AIR", al riavvio ripartiva con l'interfaccia rossa "ON AIR" ma senza un reale processo di streaming attivo, causando incoerenza.
    - *Soluzione*: Utilizzata l'opzione `partialize` del middleware `persist` in Zustanda.
    - *Logica*:
      ```typescript
      partialize: (state) => ({
          selectedDeviceId: state.selectedDeviceId,
          selectedDeviceLabel: state.selectedDeviceLabel,
          streamConfig: state.streamConfig
          // isStreaming e streamStatus sono ESCLUSI
      }),
      ```
    - *Risultato*: Al riavvio, `isStreaming` viene sempre inizializzato a `false` e `streamStatus` a `disconnected`, indipendentemente dallo stato precedente.
