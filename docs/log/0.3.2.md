## Fix applicati

### M4 — App.tsx + ffmpeg-manager.ts: console.log in produzione
**File:** `src/renderer/App.tsx`, `src/main/streaming/ffmpeg-manager.ts`

**Problema:** Numerosi `console.log` erano presenti in percorsi critici del main process e del renderer, producendo output verboso nei log di produzione e potenzialmente esponendo URL con credenziali mascherato (logUrl).

**Fix:** Rimossi tutti i `console.log` non essenziali da entrambi i file. Mantenuti i soli `console.error` per errori fatali (spawn FFmpeg fallito, taskkill fallito) che richiedono tracciamento.

```diff
-  console.log(`[StreamManager] Starting Stream (HTTP RAW + Header Fix)`);
-  console.log(`[StreamManager] Device: "${cleanDevice}"`);
-  console.log(`[StreamManager] Target: ${logUrl}`);
-  console.log('Spawning FFmpeg:', ffmpegPath, args.join(' '));
-  console.log(`FFmpeg: ${message.trim()}`);
-  console.log(`[StreamManager] Process exited with code ${code}`);
-  console.log('[StreamManager] Killing process tree...');
-  console.log("Stream Status:", status, message);  // App.tsx
```

### M2 — ffmpeg-manager.ts: bitrate hardcoded 128kbps
**File:** `src/main/streaming/ffmpeg-manager.ts`, `src/renderer/store/useStore.ts`, `src/renderer/components/SettingsPanel.tsx`

**Problema:** Il bitrate MP3 era hardcoded a `'128k'` nell'array args FFmpeg. Nessun broadcaster professionale può accettare di non avere controllo sul bitrate di encoding.

**Fix:** Aggiunto campo `bitrate: string` a `StreamConfig` (store e ffmpeg-manager). Default: `'128'`. Aggiunto `<select>` in `SettingsPanel` con i valori comuni (64/96/128/192/256/320 kbps). Il campo viene persistito nel localStorage (a differenza della password).

```diff
 interface StreamConfig {
+    bitrate: string;
 }

-  '-ab', '128k',
+  '-ab', `${bitrate || '128'}k`,
```

### M3 — App.tsx: nessuna validazione input prima di avviare FFmpeg
**File:** `src/renderer/App.tsx`

**Problema:** `toggleStream()` passava il config a FFmpeg senza validare i campi obbligatori. Un `host` vuoto o una `port` non numerica causava crash FFmpeg con messaggi di errore incomprensibili per l'utente.

**Fix:** Aggiunta validazione esplicita in `toggleStream()` prima di `startStream()`:
- `host`: non deve essere vuoto
- `port`: deve essere un numero intero tra 1 e 65535
- `password`: non deve essere vuota

Ogni fallimento imposta `errorMessage` con un messaggio leggibile, mostrato dal toast esistente.

```diff
 const toggleStream = () => {
+    if (!streamConfig.host.trim()) { setErrorMessage('Host is required.'); return; }
+    const portNum = parseInt(streamConfig.port, 10);
+    if (!streamConfig.port.trim() || isNaN(portNum) || portNum < 1 || portNum > 65535) {
+        setErrorMessage('Port must be a number between 1 and 65535.'); return;
+    }
+    if (!streamConfig.password.trim()) { setErrorMessage('Password is required.'); return; }
```
