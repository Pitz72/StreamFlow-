**Data:** 2026-05-17
**Tipo:** Fix metadata via raw socket (BUTT-compat) + sistema log a video

## Premessa

Dopo v0.5.2 sapevamo che il `MetadataManager` poteva mentire (fix onesto della validazione) ma non sapevamo perché Liquidsoap harbor di AzuraCast non processava la richiesta. L'utente ha fatto notare un fatto chiave: **BUTT funziona** con la stessa identica configurazione. Quindi il harbor accetta `/admin/metadata`, ma noi sbagliamo a costruire la richiesta.

## Ricerca codice BUTT

Repository di riferimento: [romansavrulin/butt](https://github.com/romansavrulin/butt) (mirror del SourceForge ufficiale).
File rilevante: `src/icecast.cpp`, funzione che invia metadata (intorno alla riga 352):

```c
snprintf(send_buf, sizeof(send_buf), "GET /admin/metadata?mode=updinfo&mount=%s&song=%s "
                                     "HTTP/1.0\r\n"
                                     "User-Agent: %s\r\n"
                                     "Authorization: Basic %s\r\n",
                                     mount, song_buf, PACKAGE_STRING, util_base64_enc(auth));
sock_send(&web_socket, send_buf, strlen(send_buf), SEND_TIMEOUT);

// Poi separatamente:
snprintf(send_buf, sizeof(send_buf), "Host: %s:%d\r\n\r\n", ...);
sock_send(&web_socket, send_buf, strlen(send_buf), SEND_TIMEOUT);
```

Encoding: solo manuale, sostituzione di `' '` → `%20` e `'&'` → `%26`. Niente altro.

## Differenze con StreamFlow ≤ v0.5.2

| | BUTT | StreamFlow v0.5.2 |
|---|---|---|
| HTTP version | **HTTP/1.0** | HTTP/1.1 (default Node) |
| Mount | letterale (`mount=/`) | url-encoded `/` → `%2F` (poi corretto in v0.5.2) |
| Song | solo spazi+`&` escaped | `encodeURIComponent` (encoda anche `:`, `=`, accenti, ecc.) |
| Headers | solo User-Agent, Authorization, Host | + default Node (Connection, ecc.) |
| Trasporto | TCP raw via socket | http.request (alto livello) |

Il sospetto principale era **HTTP/1.0 + headers minimali**. Liquidsoap harbor non è un server HTTP completo, è un parser semplificato che si aspetta richieste molto "pulite". HTTP/1.1 + Connection: keep-alive + transfer-encoding lo mandano in confusione.

Node `http.request` non permette di forzare HTTP/1.0 — bisogna scrivere il pacchetto a mano via `net.Socket`. Fatto.

## Modifiche

### `src/main/streaming/metadata-manager.ts` (riscritto)

- Sostituito `http.request` con `net.Socket`.
- Costruzione manuale della request line + 3 headers, replicando esattamente BUTT:
  ```
  GET /admin/metadata?mode=updinfo&mount=<MOUNT_RAW>&song=<SONG_ENC> HTTP/1.0\r\n
  User-Agent: StreamFlow/0.5.3 (BUTT-compat)\r\n
  Authorization: Basic <BASE64>\r\n
  Host: <HOST>:<PORT>\r\n
  \r\n
  ```
- Encoding `buttEncode()`: solo `' '` → `%20`, `'&'` → `%26`. Funzione privata.
- Mount mai url-encoded: passa letterale (es. `/` o `/live`).
- Risposta letta come testo grezzo, parsata manualmente: `parseRawHttpResponse()` estrae status + headers + body.
- `evaluateResponse()` valuta:
  - HTTP ≥400 → error con body trimato
  - XML Icecast `<return>1</return>` → success
  - XML Icecast `<return>0</return>` → error con `<message>` estratto
  - HTTP 2xx con body vuoto → success (è come risponde Liquidsoap harbor)
  - Altro → error generico
- Nuova interfaccia di ritorno `MetaSendResult`: `ok`, `httpStatus?`, `requestLine`, `rawResponse`, `error?` — il chiamante può mostrare la risposta grezza per debug.
- Nuovo `setLogSink()` per inoltrare eventi al sistema di log a video.

### `src/main/streaming/ffmpeg-manager.ts`

- Aggiunto `setLogSink()` parallelo a quello del MetadataManager.
- Sostituito `console.log` con `this.log('info', ...)` nei punti chiave: connecting, stream live, stream chiuso, errore di chiusura. Console.log di backup mantenuto in `this.log()`.

### `src/main/ipcp.ts`

- Nuova funzione `emitLog(level, source, message)` che invia evento `LOG_EVENT` al renderer via `webContents.send`.
- `metadataManager.setLogSink((level, msg) => emitLog(level, 'metadata', msg))` agganciato all'init.
- Stessa cosa per `streamManager`.
- `update-metadata` handler ora ritorna `httpStatus`, `requestLine`, `rawResponse` oltre a `ok`/`error`.

### `src/preload/index.ts` + `src/renderer/env.d.ts`

- Esposto `onLogEvent(callback) => unsubscribe` nel contextBridge per ricevere `LOG_EVENT`.
- Tipo `updateMetadata` aggiornato per includere `httpStatus`, `requestLine`, `rawResponse` opzionali.

### `src/renderer/store/useStore.ts`

- Nuova interface `LogEvent { id, ts, level, source, message }` (esportata).
- Stato `logEvents: LogEvent[]` (massimo 50, FIFO).
- Action `appendLog(e)` con dedup id + ts auto-generati.
- Action `clearLog()`.

### `src/renderer/components/StreamLog.tsx` (nuovo)

- Barra fissa in basso, sempre visibile.
- Modalità compatta: timestamp + badge sorgente + ultimo messaggio in monospace, bottone "Log [N]" + "Clear".
- Modalità espansa (toggle ▲/▼): lista scrollabile (max-h-64) di tutti gli eventi con autoscroll quando arriva un nuovo evento (solo se l'utente è già in fondo).
- Codifica colore: info=stone-400, success=green-400, error=red-400.
- Badge sorgente: stream=blu, metadata=viola, system=stone.

### `src/renderer/components/NowPlayingPanel.tsx`

- Stato `lastDebug` con `requestLine`, `rawResponse`, `httpStatus`.
- Bottone "Dettagli risposta server (HTTP N)" che apre un riquadro con request + raw response in font mono, max-h-48 scrollable.
- Errore toast da 8s → 10s (più tempo per leggere messaggi lunghi).

### `src/renderer/App.tsx`

- Import + montaggio `<StreamLog />` come ultimo figlio del flex column.
- `useEffect` aggiunto: subscribe a `onLogEvent` e dispatch a `appendLog`.
- Main ha ora `overflow-hidden` (la barra di log occupa lo spazio in basso e il main resta perfettamente centrato).
- Header version 0.5.2 → 0.5.3.

   - `[metadata] → host:port GET /admin/metadata?mode=updinfo&mount=/&song=Artist%20-%20Title HTTP/1.0`
