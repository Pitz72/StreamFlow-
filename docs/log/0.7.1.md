## 2. C2 — Registrazione locale via muxer tee

**Obiettivo:** copia MP3 locale della diretta senza secondo encoding e SENZA rischi per il percorso di streaming validato in diretta.

### Scoperte dalla validazione headless (importanti)

1. **Le opzioni http globali NON si propagano dentro il tee.** Con `-method PUT -headers ... -f tee`, lo slave http riceveva POST chunked con User-Agent Lavf e senza Authorization → il harbor avrebbe rifiutato. Soluzione: opzioni passate **per-slave** (`[f=mp3:method=PUT:chunked_post=0:content_type=audio/mpeg:headers=...]url`).
2. **Doppio escaping dei `:` negli header.** Il tee fa due livelli di parsing (split slave su `|`, poi opzioni su `:`), ognuno consuma un livello di `\`: un `:` letterale richiede `\\:` nell'argomento (helper `teeEscapeOptionValue`). Verificato con server TCP raw: la request line è `PUT /live HTTP/1.1` con tutti gli header BUTT-compat, identica al percorso singolo.
3. **Slave http fallito ≠ processo morto.** Se il server rifiuta la connessione in apertura, il tee logga `Slave muxer #0 failed ... continuing` e CONTINUA con il solo file: l'app sembrerebbe ON AIR registrando muta. Gestito in `ffmpeg-manager`: il pattern viene riconosciuto su stderr → kill del processo + status `error`.

### Comportamento

- Toggle in Configurazione (`recordLocal`, persistito, default off).
- File: `Documenti/StreamFlow/RuntimeRadio_YYYY-MM-DD_HH-MM-SS.mp3`, uno per sessione; l'auto-reconnect rilancia `launch()` → nuovo file (split automatico su drop).
- `onfail=ignore` SOLO sullo slave file: errore disco → `Slave muxer #1 failed` → log "la diretta continua"; errore di connessione → FFmpeg esce → auto-reconnect invariato.
- Se `recordLocal` è off, gli argomenti FFmpeg sono **byte-identici** a v0.7.0 (nessun rischio di regressione sul percorso provato).

## 3. VU meter post-gain

Le lancette ora riflettono il volume input (anche live): `useAudioVisualizer` moltiplica il livello per `inputGain/100` letto dallo store via `useStore.subscribe` → ref (zero re-render, zero modifiche alla pipeline Web Audio). Matematicamente equivalente al filtro `volume` FFmpeg (lineare).
