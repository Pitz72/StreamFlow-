## Fix #1 — AzuraCast/Liquidsoap harbor

### Root cause confermato
In AzuraCast con backend Liquidsoap, Liquidsoap è connesso **permanentemente** come sorgente al mount listener Icecast (es. `/radio.mp3` su porta 8000). Il DJ **non** deve connettersi a Icecast direttamente: deve puntare all'**input harbor di Liquidsoap**, che gira su una porta separata (default `8005`) con mount default `/`.

Il Wizard v0.5.0 estraeva host/port/mount dal `listen_url` pubblico → portava lo stream contro Icecast → 401 superato, poi RST mid-stream perché il mount era occupato.

### Conferma da pannello Runtime Radio (utente)
- Server: `player.runtimeradio.com`
- Porta DJ: **8005**
- Mount DJ: **`/`**
- Auth: `dj_username:dj_password`

### Modifiche

**`src/main/azuracast/azuracast-api.ts`**
- Nuova funzione `tryFetchHarborConfig(baseUrl, apiKey, stationId)` chiama `GET /api/admin/station/{id}` e ritorna `backend_config.dj_port` + `dj_mount_point`. Cattura ogni errore (auth/network/parsing) e ritorna `null` → fallback silenzioso.
- `fetchJson` ora verifica `res.statusCode` e rigetta su non-2xx (prima parsava JSON anche su error responses).
- `fetchStationDetail`:
  - host derivato dal `listen_url.hostname` (corretto: stesso hostname pubblico).
  - port/mount: prova `tryFetchHarborConfig` → se OK usa quei valori, altrimenti default `8005` / `/`.
  - Aggiunto flag `harborInferred: boolean` al ritorno (true = fallback usato).

**`src/renderer/env.d.ts`**
- Aggiunto `harborInferred: boolean` all'interfaccia `AzStationDetail`.

**`src/renderer/components/AzuraCastWizard.tsx`**
- Step 3 del wizard ha ora due input editabili pre-Applica:
  - `Porta DJ` (pre-compilata con `detail.port`)
  - `Mount DJ` (pre-compilato con `detail.mount`, normalizzato per iniziare con `/`)
- Banner verde "✓ Porta DJ letta automaticamente dall'API admin" se `harborInferred === false`.
- Banner giallo con istruzioni "verifica in AzuraCast → Broadcasting → How do I connect? → Icecast Clients" se `harborInferred === true`.
- `INFO_TEXT` aggiornato per richiedere il permesso "Manage Station Broadcasting" sull'API Key (necessario per leggere `backend_config`).
- `apply()` usa i valori editabili `editPort/editMount`, non più direttamente `detail.port/detail.mount`.

**`src/main/streaming/ffmpeg-manager.ts`**
- Aggiunto log diagnostico all'avvio: `[StreamManager] Connecting → host:port/mount as user="..."`.
- Tracciato nuovo flag `streamingStarted` (true al primo `size=`/`time=`).
- Nel close handler, riconosciuto il pattern "auth OK + RST immediato senza streaming" (regex su `-10053|WSAECONNABORTED|Error muxing|Connection reset` + `!streamingStarted`) → mostra messaggio esplicito:
  > *"Server ha chiuso la connessione subito dopo l'auth. Probabile causa: mount/porta sbagliati (stai puntando a Icecast invece che al harbor Liquidsoap?). Verifica che porta=X e mount=Y corrispondano a 'Icecast Clients' nel pannello AzuraCast → Broadcasting → How do I connect?"*

## Fix #2 — Sidebar non scrollabile (bug UX scoperto durante i test)

Sintomo: il pulsante "✓ Applica configurazione" del Wizard non era visibile.
Causa: la `<aside>` in App.tsx aveva `flex flex-col` senza `overflow-y-auto`, e il root aveva `overflow-hidden`. Il contenuto che eccedeva l'altezza viewport veniva troncato senza scrollbar.
Fix: aggiunto `overflow-y-auto` alla aside.

(Questo fix è stato poi superato dal refactor UI completo descritto sotto, che ha eliminato la sidebar.)

## Refactor UI

### Motivazione
L'utente ha richiesto di eliminare la sidebar e i pannelli che ingombravano la schermata principale, sostituendoli con pulsanti che aprono modali specifici.

### Nuova struttura

**`src/renderer/components/Modal.tsx` (nuovo)**
- Componente generico riutilizzabile.
- Backdrop semi-trasparente con blur, click chiude.
- `Esc` chiude (event listener montato solo quando `isOpen`).
- Card centrata con `max-h-[90vh]` e scroll interno se contenuto eccede.
- Header con titolo + bottone ✕.
- Prop `maxWidth` per dimensionamento (default `max-w-md`).

**`src/renderer/App.tsx` (riscritto)**
- Layout root: `flex flex-col h-screen` (verticale, non più orizzontale con sidebar).
- Header in alto: status indicator (pallino + label colorata Ready/Connecting/ON AIR/Error) + 3 pulsanti toolbar (Now Playing, Cover Art, Configurazione) + versione.
- Main: solo Timer + VU Meters L/R + pulsante ON AIR centrati verticalmente.
- 3 modali registrati con `openModal: null | 'settings' | 'nowplaying' | 'coverart'`.
- Validazione GO ON AIR: se manca un campo obbligatorio, **apre automaticamente il modale Configurazione** oltre a mostrare il toast.

**`src/renderer/components/CoverArtPanel.tsx`**
- Rimosso il toggle interno `open/setOpen`: il pannello è sempre montato, l'apertura è gestita dal Modal contenitore.
- Rimosso wrapper card con bordo viola e header interno (ridondanti con il Modal).

**`src/renderer/components/NowPlayingPanel.tsx`**
- Rimosso wrapper `max-w-2xl bg-stone-900/50 rounded-xl border ...` e `<h3>Now Playing / Metadata</h3>` (ridondanti con il Modal).

**`src/renderer/components/SettingsPanel.tsx`**
- Rimosso `<h2>Settings</h2>` (ridondante con titolo Modal).
- Rimosso il badge di stato in fondo (ora vive nell'header globale).
- Rimossi gli import e l'uso di `streamStatus`.
