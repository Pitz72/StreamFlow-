# Runtime StreamFlow v0.1.2 Log

## Data: 2026-03-05
## Versione: 0.1.2 (Critical Fix: FFmpeg Production Path)

### Stato: IMPLEMENTED
Risolto bug critico che impediva al binario FFmpeg di essere eseguito nelle build di produzione (.exe installato).

### 🔴 Fix Critico: FFmpeg binario inaccessibile in produzione (Asar)

#### Diagnosi
Il progetto utilizza `ffmpeg-static` per fornire il binario FFmpeg. In fase di sviluppo, il path `node_modules/ffmpeg-static/ffmpeg.exe` è accessibile direttamente dal filesystem. Tuttavia, in produzione Electron impacchetta l'applicazione in un archivio **asar** (simile a un archivio zip), e i binari all'interno di un asar **non possono essere eseguiti** tramite `child_process.spawn()`.

#### Causa Root
Due configurazioni mancanti:
1. **Nessun `asarUnpack`**: electron-builder non estraeva il binario FFmpeg dall'archivio asar.
2. **Nessuna correzione path**: Il codice usava il path grezzo di `ffmpeg-static`, che in produzione puntava dentro `app.asar` (ineseguibile).

#### Soluzione Applicata

**1. Configurazione `asarUnpack` in `package.json`**

Aggiunta la direttiva `asarUnpack` alla sezione `build` di electron-builder:

```json
"asarUnpack": [
  "**/node_modules/ffmpeg-static/**"
]
```

Questo indica a electron-builder di estrarre l'intera directory `ffmpeg-static` fuori dall'archivio asar, posizionandola nella cartella parallela `app.asar.unpacked/`.

**Layout risultante in produzione**:
```
resources/
├── app.asar                          ← Archivio principale
└── app.asar.unpacked/
    └── node_modules/
        └── ffmpeg-static/
            └── ffmpeg.exe            ← Binario eseguibile, accessibile da spawn()
```

**2. Correzione path in `ffmpeg-manager.ts`**

Il path restituito da `ffmpeg-static` viene ora normalizzato automaticamente:

```typescript
// Prima (v0.1.1):
import ffmpegPath from 'ffmpeg-static';
// → In produzione: "C:\...\app.asar\node_modules\ffmpeg-static\ffmpeg.exe" (ERRORE)

// Dopo (v0.1.2):
import ffmpegPathRaw from 'ffmpeg-static';
const ffmpegPath = ffmpegPathRaw?.replace('app.asar', 'app.asar.unpacked') ?? null;
// → In produzione: "C:\...\app.asar.unpacked\node_modules\ffmpeg-static\ffmpeg.exe" (OK)
// → In sviluppo: path invariato (non contiene "app.asar"), nessun side effect
```

### Note Tecniche
- La sostituzione `app.asar` → `app.asar.unpacked` è un pattern standard documentato da Electron per i moduli nativi e binari esterni.
- In modalità sviluppo il path non contiene `app.asar`, quindi `.replace()` non ha effetti e il comportamento resta identico.
- L'operatore `??` gestisce il caso in cui `ffmpeg-static` restituisca `null` (binario non trovato), propagandolo correttamente al controllo `if (!ffmpegPath)` esistente nella funzione `start()`.
