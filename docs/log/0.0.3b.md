# Runtime StreamFlow v0.0.3b Log

## Data: 2026-02-07
## Versione: 0.0.3b (Patch: Icecast User Support)

### Stato: IMPLEMENTED
Aggiunto il supporto per l'autenticazione con username specifico (DJ Mode) su server Icecast, funzionalità mancante rispetto a client come BUTT.

### Nuove Funzionalità
- **Icecast User (DJ Mode)**: 
  - Nuovo campo "Icecast User" nel pannello impostazioni.
  - Default: 'source' (comportamento standard Icecast).
  - Supporto per username arbitrari (es. 'dj_name', email).
- **Sicurezza URL**:
  - Implementato encoding sicuro per User e Password nell'URL di connessione (`encodeURIComponent`).
  - Questo previene errori di connessione se le credenziali contengono caratteri speciali (es. '@', ':', '/').
- **Debug**:
  - Il backend ora logga l'URL di connessione mascherando la password per facilitare il debug senza esporre credenziali.

### Modifiche Tecniche
- **Store**: Aggiornato `useStore.ts` con il campo `icecastUser`.
- **UI**: Aggiornato `SettingsPanel.tsx` con input dedicato.
- **Backend**: Aggiornato `ffmpeg-manager.ts` per costruire l'URL nel formato `icecast://user:password@host...`.

### Problemi Risolti
- **Dev Mode / Hot Reload**: 
  - *Problema*: Il comando `npm run electron:dev` caricava i file statici della build precedente (`dist`) invece del server di sviluppo Vite, impedendo la visualizzazione delle modifiche live (es. campo Icecast User mancante).
  - *Causa*: Mancata impostazione della variabile d'ambiente `NODE_ENV=development` nello script di avvio.
  - *Fix*: Aggiornato `package.json` con `cross-env NODE_ENV=development` nel comando `electron:dev`. Ora Electron carica correttamente da `http://localhost:5173`.

- **Audio Device Selection**:
  - *Problema*: FFmpeg su Windows con `dshow` fallisce se si usa `audio=default` (errore `Could not enumerate audio only devices`).
  - *Fix*: Aggiornata logica in `App.tsx`. Ora viene passato il *nome* del device (Label) al backend invece dell'ID o "default".
  - *UX*: Aggiunto controllo che impedisce lo streaming se è selezionato "Default System Device", chiedendo all'utente di scegliere un device specifico (es. "Microfono (Realtek)").

- **Security Warning**:
  - *Problema*: Warning persistente in console `Insecure Content-Security-Policy` dovuto a `unsafe-eval` (necessario per Vite).
  - *Fix*: Aggiunto env var `ELECTRON_DISABLE_SECURITY_WARNINGS=true` nello script `electron:dev` per pulire la console in fase di sviluppo.

- **DevTools**:
  - *Richiesta*: La console sviluppatore si apriva automaticamente all'avvio.
  - *Fix*: Disabilitata l'apertura automatica di DevTools in `main.ts` (commentata la riga `mainWindow.webContents.openDevTools()`).

### Note
Nessuna nuova build (.exe) generata per questa patch. Le modifiche sono a livello di codice sorgente e pronte per la prossima release cumulativa.
