### 🟡 Fix Medio M4: Timer "Stuttering" Optimization

#### Diagnosi
`Timer.tsx` utilizzava un approccio standard ingenuo per l'orologio interno:
```tsx
setInterval(() => { setSeconds(s => s + 1); }, 1000);
```
In JavaScript puro (e specialmente in React/Electron limitati dal main Event Loop), un set interval temporizzato a `1000ms` esatti subisce il fenomeno del "drift". Variazioni nell'event loop (ad esempio causati da altri ri-rendering UI) facevano accumulare micro-ritardi e in alcuni secondi rendevano il timer percepibilmente scattoso e non sincronizzato col "vero" secondo fisico globale.

#### Soluzione Applicata
L'algoritmo del timer è stato riscritto basandolo su calcolo Unix Assoluto (`Date.now()`) rendendo il timer indistruttibile dai drop di framerate.
1. Utilizzato `useRef` per storare lo `startTimeRef` (il millisecondo esatto della connessione).
2. Il `setInterval` interno è stato abbassato a `500ms` (un polling più rapido e reattivo per intercettare lo scatto).
3. Ad ogni tick, invece di fare matematica incrementale cieca (`s+1`), il motore deduce i secondi totali dal delta assoluto: `Math.floor((now - startTimeRef.current) / 1000)`.  
Questo garantisce precisione UTC e azzera il drift accumulativo.
